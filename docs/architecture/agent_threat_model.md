# AI Agent Threat Model & Runtime Controls

This document details the threat model for **VulScanAgent**, structured in accordance with the **STRIDE** methodology and the **OWASP Top 10 for Agentic AI Applications**, referenced from [awesome-agent-security](https://github.com/basitalisandhu/awesome-agent-security).

---

## 1. What Makes Agent Security Unique?

Unlike conventional chatbots or static code analyzers, an **autonomous AI agent** is an LLM connected to privileged tools, filesystems, and APIs. It reads untrusted source code and can execute commands and write files.

```
       ┌────────────────────────┐
       │   Untrusted Input      │  (Target repo code, comments, dependencies)
       └───────────┬────────────┘
                   │
                   ▼
       ┌────────────────────────┐
       │   AI Agent Reasoning   │  (FixArchitect, SecurityReviewer, etc.)
       └───────────┬────────────┘
                   │
         [ Runtime Guardrail Gate ]  ◄── Enforces path safety & secret redaction
                   │
                   ▼
       ┌────────────────────────┐
       │ Privileged Tool Exec   │  (Git branches, file writes, tests, PRs)
       └────────────────────────┘
```

Securing an autonomous agent requires:
1. **Controlling what it can touch** (Filesystem & Path boundaries).
2. **Isolating what it runs** (Subprocess & Container sandboxing).
3. **Filtering what it loads** (Prompt injection quarantine).
4. **Validating what it emits** (AST syntax parsing & secret redaction).

## 2. STRIDE Threat Analysis & Implemented Countermeasures

| Threat Category | Potential Attack Vector | VulScanAgent Countermeasure |
|---|---|---|
| **S - Spoofing** | Forged GitHub webhook payloads triggering unauthorized repo scans. | **Cryptographic Verification**: Enforces `HMAC-SHA256` signature verification (`X-Hub-Signature-256`) via `hmac.compare_digest`. |
| **T - Tampering** | Agent hallucination or untrusted repo content corrupting business logic or planting backdoors. | **Dual Gate & Re-scan**: Patches must pass `ast.parse()` syntax validation, `SecurityReviewer` audit, test suite pass, and re-scan eradication proof. |
| **R - Repudiation** | Disputed changes or unverified modifications in production. | **Audited Git Commits & PRs**: Isolated branches (`fix/vuln-*`), commit SHAs, and executive audit documentation generated by `PRAuditor`. |
| **I - Information Disclosure** | Leaking private keys, database passwords, or PATs into PR comments or logs. | **Automated Secret Redaction**: `AgentGuardrails.redact_secrets()` masks AWS, GitHub, OpenAI keys, and private keys prior to any output. |
| **D - Denial of Service** | Malicious recursive test commands or massive file bombs causing resource exhaustion. | **Strict Resource Quotas**: `validate_patch_size()` limits file lengths; `subprocess.run` sets strict 180s timeout; max retries capped at 3. |
| **E - Elevation of Privilege** | Code escaping repository directory (`../../etc/passwd`) or executing host root commands. | **Path Traversal Shield**: `validate_safe_path()` resolves real paths against `repo_dir.resolve()`; `no-new-privileges: true` in Docker. |

## 3. OWASP Top 10 for Agentic AI (ASI) Mapping

| ASI ID | Risk Name | How VulScanAgent Defends |
|---|---|---|
| **ASI01** | Agent Hijacking & Indirect Prompt Injection | All repository code is quarantined inside `<untrusted_source_code_quarantine>` blocks; system prompt explicitly orders the model to disregard instructions embedded in code comments. |
| **ASI02** | Tool Misuse & Excessive Privilege | Strict **Zero Auto-Merge Policy**; agent can only open branches and PRs; never allowed to push directly to `main` or merge. |
| **ASI03** | Insecure Tool Parameterization | Commands executed by `TestRunner` are passed as sanitized argument lists (`shell=False`); raw shell chaining operators (`;`, `&&`, `$()`) are blocked. |
| **ASI04** | Secret Exfiltration via Agent Logs | Credentials are scrubbed in-memory via regex entropy scanners before writing to logs, terminal output, or GitHub PR descriptions. |
| **ASI05** | Unbounded Loop Execution | Fix attempts are strictly bounded by `ai.max_fix_retries` (default 3); tests timeout at 180s. |
| **ASI06** | Insecure Output Handling | Fixes are parsed by native AST before write; invalid syntax never touches the filesystem. |

## 4. Runtime Guardrails Engine Architecture (`agent/security/guardrails.py`)

The runtime guardrails engine sits as an inline security policy proxy:

```python
from agent.security.guardrails import AgentGuardrails

# 1. Path Safety Check
safe_file = AgentGuardrails.validate_safe_path(repo_dir, file_path)

# 2. Command Sanitization
clean_cmd = AgentGuardrails.sanitize_command(["pytest", "-v"])

# 3. Secret Scrubbing
scrubbed_pr_body = AgentGuardrails.redact_secrets(raw_pr_body)

# 4. Patch Size Guard
AgentGuardrails.validate_patch_size(new_code)
```
