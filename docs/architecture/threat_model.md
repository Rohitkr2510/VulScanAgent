# Threat Model & Security Boundaries

## 1. Security Philosophy

Because **VulScanAgent** inspects, repairs, and tests source code autonomously, the agent itself must adhere to strict defensive security practices. An automated security agent must never introduce security risks to host systems or codebases.

---

## 2. Threat Vectors & Mitigations

| Threat | Risk Level | Mitigation Strategy |
|---|---|---|
| **Remote Code Execution (RCE) via Target Tests** | HIGH | Target tests execute within isolated subprocesses or hardened Docker containers with dropped privileges (`no-new-privileges: true`). |
| **Credential / Token Leakage** | CRITICAL | All credentials (PATs, API keys) are masked before logs or PR descriptions are created. `.env` is gitignored. |
| **Malicious Repository Content** | HIGH | Repositories are cloned with depth 1. Subprocesses never execute in shell mode (`shell=False`). |
| **Hallucinated or Flawed Fixes** | MEDIUM | Dual verification gates: AST syntax validation + `SecurityReviewer` critique + automated test pass requirement. |
| **Unauthorized Code Merging** | HIGH | **Zero Auto-Merge Policy**: All agent output is delivered via Pull Requests requiring human approval. |

---

## 3. Sandboxing & Isolation Guarantees

### 3.1 Execution Boundaries
```
Host System
   │
   ├── [Container / Subprocess Boundary]
   │      ├── Read-Only Root Filesystem (optional)
   │      ├── Dropped Privileges (non-root UID)
   │      ├── CPU & Memory Quotas
   │      └── Temporary Clone Directory (purged upon completion)
   │
   └── Isolated Git Working Tree
          └── Isolated Branch: fix/vuln-<id>
```

### 3.2 Credential Handling
- GitHub Personal Access Tokens (PATs) are used strictly via in-memory git transport (`https://x-access-token:<token>@github.com/...`) and never written to `.git/config` on disk.
- AI Provider API keys are read exclusively from process environment variables and are never echoed into agent logs, PR comments, or test reports.

### 3.3 Static AST Pre-Validation
Before any file generated by an AI agent is written to disk or tested, it is parsed by the language's native Abstract Syntax Tree parser (e.g. Python's `ast.parse()`, `json.loads()`, `yaml.safe_load()`). Code that fails syntax parsing is immediately rejected without execution.
